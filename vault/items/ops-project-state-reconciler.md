Reads the live signals and compares them with `project_state/` and the OpenHouse company memory, then drafts a minimal update or patch for only the notes that drifted. It should preserve human review for any contradiction and keep the canonical state aligned after each sync.

## Incubation analysis, 18 July 2026

### Opportunity size
This has high portfolio leverage because stale state is already affecting decisions: OpenBook and Evolv have not been live-refreshed since 1 July, while OpenHouse checks are current. Better reconciliation reduces repeated research and prevents work being prioritised against old facts.

### Technical approach, risks and effort
Create a source hierarchy, compare timestamped live observations with canonical claims, and draft minimal patches with provenance. Never overwrite unresolved contradictions. Medium setup effort is justified only if the reconciler distinguishes unknown, blocked and unchanged states. The central risk is converting an unavailable check into a false statement that nothing changed.

### Market timing and recommendation
Agentic operations increase the value of reliable shared state, but correctness matters more than automation breadth. This is mature enough for a bounded internal project after Cara's P0 measurement gap. First scope should cover only project_state timestamps, GitHub facts and explicit unavailable checks.

### Value category

- **Risk reduction:** surfaces unpublished heads, dirty checkouts, conflicts and candidate-identity ambiguity before cleanup, machine failure or a mistaken handoff.
- **Decision quality:** separates source custody from implementation, deployment, rendered acceptance and venture activation.
- **Time reclaimed:** replaces repeated manual `worktree`, branch-containment and status reconstruction during project-state reconciliation.

### Smallest live test

Run one read-only inventory over the already named local repositories/worktrees for Aire, OpenBook and parked Cara. For each checkout record repository, worktree path, branch or detached state, exact head, clean/dirty/conflicted state, upstream, remote branches containing the head, divergence from the nominated parent/default branch, latest commit date, canonical project status and whether Ground Zero already names that candidate. Emit only a draft custody manifest and exceptions list; do not inspect secrets or source contents beyond Git metadata.

### Evidence of success

- The manifest reproduces the known Aire `83e582c`, OpenBook `658e67a` and `de26b62`, and Cara `196cf3c`, `73de73a`, `464b1ef` and `03b4d99` custody boundaries from their current project-state notes.
- It flags every no-upstream or non-remotely-contained head, the OpenBook conflict and the contradictory dirty Aire root checkout without calling any candidate deployed, accepted or active.

- A manual spot-check of `git status`, `git worktree list`, upstream configuration and remote containment finds no omitted checkout or unsupported classification.
- A second unchanged run produces no alert, while a newly dirty or newly uncontained head produces one concise exception.

### Downside and failure mode

Keep the first test to repositories already named in Ground Zero, store no source bodies or secrets, distinguish intentional local-only state from unresolved risk, and treat unknown ownership or purpose as `UNKNOWN`, not urgent failure.

### Bottleneck

The reconciler is detecting the same failure without producing enough evidence to shorten diagnosis. [[project_state/personal-agent]] records the canonical Aire BFF route offline across repeated four-hour checks on 23–25 August. The current sweep proves degradation repeatedly, but Sam or a coding agent still has to reconstruct launch configuration, process chronology, log freshness, dependency health and the earliest failed stage by hand.

### Value category

- **Reliability and risk reduction:** converts a generic offline signal into a bounded, reviewable failure boundary without restarting or mutating anything.
- **Time reclaimed:** stops paying for repeated four-hour prose that says the same route is absent while leaving diagnosis untouched.
- **Decision quality:** distinguishes launch failure, missing dependency, port-binding failure, stale log evidence and `UNKNOWN` instead of treating every absent listener as one condition.

### Smallest live test

Run one read-only collector against the already named canonical Aire BFF launchd job and use the 24–25 August observations as the comparison fixture. Capture only whitelisted, non-secret evidence: job label, executable path, working directory, redacted argument shape, file ownership and permissions, last exit status, launch count and timestamps, bounded recent stdout/stderr metadata and redacted lines, expected-port listeners, and health of the explicitly named local Hermes origin. Compare that packet with the latest canonical observation and emit one deterministic incident fingerprint plus an ordered failure-stage classification. Do not read environment-variable values, credential files, request bodies or production data.

### Evidence of success

- The packet reproduces the known transition from last exit `1` to `2`, the absent canonical listeners and the generic-error limitation without promoting any route to healthy.
- It identifies the earliest supported failed stage—job invocation, dependency availability, bind/listen, or post-start health—or returns `UNKNOWN` with the exact missing evidence.
- A manual check of the same launchd state, process table, listener state and redacted log window agrees with every classification.
- Replaying an unchanged failure produces the same fingerprint and no new human-facing alert; a changed exit code, dependency state, listener state or fresh error signature produces one concise packet.
- The packet contains no secrets and does not claim authenticated, rendered-device or owner acceptance.

### Downside and failure mode

Logs and launch arguments can contain credentials, and stale output can be mistaken for the current crash. A noisy packet could also turn every four-hour check into another alert stream. Use a strict field allowlist, redact values before persistence, record log file identity and modification time, cap the line window, fingerprint only decision-relevant fields, and fail closed to `UNKNOWN` when evidence cannot be bound to the observed launch attempt.

### Approval boundary

Automation may read the named launchd job's non-secret metadata, process/listener state, bounded redacted logs and explicitly named local dependency health, then draft one incident packet on a material transition. It may not load, unload, kick-start, restart or kill a service; edit a plist, config, route or source file; reveal environment values; change Tailscale; bind a port; fetch or integrate code; drive a device; push, deploy or promote acceptance. Sam approves every remediation and any broader diagnostic scope.

### What it replaces

It replaces repeated manual reconstruction of the same BFF launch failure and repeated generic “offline” prose after the first unchanged observation. It does **not** replace [[items/ops-daily-sync-digest]], the change-only observation ledger above, [[items/ops-aire-hermes-upstream-impact-triage]], hands-on debugging, authenticated request checks, rendered-device verification or human restart and release decisions.
