# Donworth outcome-driven delivery standard

## Accepted norm

- Sam sets direction, prioritizes, judges consequential product choices and approves outward/irreversible actions. Skippy owns delivery and consolidated communication; Forge implements in isolated worktrees; Vera independently verifies exact candidates.
- Telegram is the CEO interface. Ground Zero owns accepted durable context; Donworth Studio Kanban owns execution; Git and retained artifacts own source/evidence. No new platform, duplicate scheduler, role swarm or competing memory database.
- Astra (`openai-codex` / `gpt-6-astra`) is the desired Skippy substantive-work default and a deliberate Forge route for difficult/high-value product and engineering work. Kimi K2.7 Code through OpenCode Go remains routine Forge default; Grok 4.6 through existing xAI OAuth remains independent Vera default. New helpers/routes need qualification. This supersedes the Sol-primary direction in [[decisions/2026-09-03-cost-efficient-agent-model-routing]]; its privacy exclusions and approval boundaries remain in force. Desired routing and effective runtime routing must be reported separately.
- Quick requests bypass the pipeline. Bounded work uses a compact existing card. Release, native, integration and client-sensitive missions use controlled contracts and proportionate exact-artifact evidence.
- Mission approval covers named sources/worktree, permitted reversible local changes, tests, local commits, previews, budget and stop conditions. Batch consequential approvals against an exact candidate and target; no blanket standing authorization for future Ground Zero writes or releases is created.
- Preserve accepted identities and requirements. Define the earliest complete customer journey, resolve integration uncertainty early, build, exercise the result, correct, polish and independently verify before presenting it as ready.
- One primary delivery mission, at most two background model workers, one heavy local build/QA workload and one desktop controller are initial admission limits. These are policy until corresponding enforcement is tested. No desktop interaction during Sam's testing without explicit coordination.
- Existing subscriptions only; no new spend, paid API fallback, top-up, external hosting or training/contributor routes for private work. Usage estimates are not provider-enforced limits. Unknown quota/spend controls keep a lane supervised-only; included-only settings and bounded admission must be verified before unattended activation.
- Cumulative budgets across retries, no repeated human-blocker wakeups, preserved checkpoints/artifacts, explicit reboot/auth/network recovery and a tested backup/restore route are required before corresponding autonomy claims. Reuse existing Hermes controls and repair only proven gaps.
- Meaningful updates only: acceptance, useful preview/material risk, and final artifact plus evidence and exact next approval. Measure accepted-delivery time, founder intervention, rework/regressions and observed usage; improvement targets are not yet measured results.
