## Procedure

1. Look for procedures that repeat across sessions.
2. Check whether the process has clear steps, pitfalls, and verification.
3. Prefer subjects with stable inputs and outputs.
4. Choose one source of truth before learning from it.
5. Use `/learn` on the source material or a concise description of the workflow.
6. Store the resulting skill or link to it from the relevant note.

## Pitfalls

- Do not use `/learn` for one-off facts.
- Do not use it for things that belong in memory instead of a skill.
- Do not train it on half-baked workflow guesses.
- Do not duplicate the same process in both a note and a skill unless the note is serving as an index.

## Verification

Confirm the learned skill has a `SKILL.md` with trigger conditions, procedure, pitfalls, and verification steps.
