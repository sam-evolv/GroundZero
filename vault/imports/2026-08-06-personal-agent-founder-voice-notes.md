# Personal agent founder voice notes

> This preserves the substance and sequencing of Sam's two voice notes. Obvious transcription noise has been cleaned, but ambiguous wording is not treated as a precise quote. The original message remains in the Hermes session history.

## Voice note one: company thesis and distribution loop

Sam has always wanted to build a subscription business. The emergence of OpenClaw and Hermes made the opportunity concrete: agents are becoming capable enough to help run a business, and the fact that the agent runs the business can itself become the marketing story.

The product thesis comes from Sam's own use of a deeply contextual personal agent and Ground Zero. If an agent has the right context about a person's life, projects, preferences and history, how far can it move that person's life forward? Sam believes the answer is materially further than normal chat products.

Most people still do not understand or use agents. Hermes is extremely capable, but even for Sam, who is technical, agent setup has involved command lines, providers, gateways and Telegram configuration. OpenClaw was much harder again. Ordinary users will not complete that setup.

The opportunity is to package the capability so a person can reach their agent as simply as sending a message. Setup must take roughly three or four minutes and must not require technical concepts.

The founder story is part of distribution: Sam had an agent that materially helped him, then used that agent to build the infrastructure and company that would give the same leverage to other people. The product, brand, design system, demonstrations and marketing assets should all be created and operated with visible agent involvement.

The distribution loop should continuously showcase concrete capabilities. Once or twice per day, publish strong demonstrations of real things the agent completed. Sam can truthfully say from his own account that the product and its marketing are being built and operated with his agent. The call to action becomes: this is what my agent did, have you got yours?

Sam may document the build and operating journey in long-form writing in parallel. The company itself becomes proof of the product.

Pricing should be accessible enough to remove hesitation. A possible entry tier around €4.99 per month could use a capable low-cost text model and omit premium image, video and expensive work. The target variable model cost for that tier is no more than roughly €1 per active user per month. This is a hypothesis to test against real usage and support cost, not a committed public price.

A home-screen widget or similarly immediate device surface may strengthen the feeling that the assistant is always available.

## Voice note two: build order

Do not attempt to invent a better agent runtime than Hermes. Duplicate the capability and behaviour Sam already has because it is effective. Change the channel and product surface first.

Near-term sequence:

1. Preserve Hermes as the underlying runtime and replicate Sam's current working setup.
2. Build a web interface over it.
3. Make that web app installable to the phone home screen so Sam can use it frequently.
4. Build a desktop experience that initially follows Hermes Desktop closely rather than redesigning agent interaction from theory.
5. Dogfood the system heavily and record what is confusing, annoying or technical.
6. Simplify progressively for ordinary users and the Irish market by working backward from observed friction.
7. Keep the current ChatGPT-linked model path temporarily where practical. Do not lock the commercial routing model early because model economics and capability are changing rapidly.
8. Once the experience is stable, introduce invisible model routing, memory architecture and cost controls.
9. When the web and desktop product are proven, create native iOS and Android versions and enter the store-review process.
10. Only then finalise model economics, plans and packaging using observed use rather than assumptions.

The working product name is not final. Do not let naming block execution.

## Durable interpretation

The first proof is founder dogfood of a broadly capable Hermes wrapper, not another narrow file utility. Product learning comes from Sam using the real assistant across varied work and life tasks. Simplification follows evidence.

The company has two compounding proof loops:

- **Product loop:** Sam uses the assistant, exposes friction, the agent improves the wrapper, and capability becomes easier to use.
- **Distribution loop:** the agent completes meaningful work, turns that work into truthful proof assets, and publishes only after Sam's approval.
