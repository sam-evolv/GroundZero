# Full Hermes Desktop parity before consumer simplification

## Source direction

Sam clarified that IrelandGPT must begin from the complete Hermes Agent and Hermes Desktop working experience, not from a pre-simplified consumer subset. The current Quiet Margin mobile/web shell is an acceptable visual starting point, but it must be filled with the full useful Hermes capability set before further consumer redesign.

The sequence is:

1. Take Hermes Agent and Hermes Desktop as the functional baseline.
2. Put an IrelandGPT brand, colour system and responsive web/mobile shell around that baseline.
3. Make every useful Hermes Desktop outcome available and genuinely operational.
4. Dogfood the complete product.
5. Only then reorganise, hide, simplify or reframe capability for mainstream Irish users.
6. Add onboarding, messaging channels, phone continuity and business-model packaging after functional parity is established.

## What full parity means

The parity ledger starts from the authoritative Hermes Desktop surface:

- chat, sessions, history, search, branching and conversation controls;
- streaming responses, live tool activity, progress and structured action summaries;
- prompt history, queued work, stop, resume and recovery;
- photos, documents, drag-and-drop files and multimodal input;
- previews and generated artifacts with safe open, download and provenance;
- approvals and consequential-action confirmation;
- voice input and spoken replies;
- skills, memory, schedules, profiles, messaging and connections;
- agents, delegation, background work and Command Center activity;
- model, reasoning and response preferences;
- settings for providers, tools, MCP and gateway capability;
- project, file, terminal and Git outcomes where a paired trusted desktop runtime is required.

A navigation label, capability card or simulated state does not count. Each outcome must use the authoritative Hermes resource, work end to end, and be exercised in the browser or paired desktop path.

## Surface and architecture rule

IrelandGPT is a product-owned wrapper around Hermes, not a replacement agent runtime. Hermes remains authoritative for sessions, runs, approvals, artifacts, memory, skills, jobs, agents, tools and connections.

Full user-outcome parity does not require exposing raw operator endpoints to a public browser. Trusted-local powers such as unrestricted terminal, filesystem and Git operations remain executed by Hermes or an explicitly paired desktop companion. They are still requested and followed through the IrelandGPT conversation and interface.

## Conversational capability discovery

Chat is the primary control surface. Connectors and settings remain discoverable in Settings, but users should not be forced through an integration catalogue.

When a task needs access, IrelandGPT asks at the point of need in plain language. Example intent:

> I can sort that. If you connect your calendar, I can organise the day around what is already in there.

The product explains why access is needed, what it can do, and whether approval is required.

## Irish soul

The assistant should feel Irish at its core without becoming a caricature.

- Use Irish English rather than American or British product language.
- Pepper responses with restrained, context-appropriate Irish phrasing.
- Prefer natural phrases such as “No bother”, “Grand”, or “I can sort that” only when they fit.
- Never force slang into serious, sensitive, formal or high-stakes situations.
- Avoid stage-Irish clichés, exaggerated dialect spelling and repetitive catchphrases.
- The personality should come through in warmth, directness, humour, understatement and local language rhythm.

Settings may offer several product-owned soul profiles, for example formal, warm, colloquial, concise and reflective. These are behavior and tone choices, not model/provider controls.

## Immediate consequence

Do not deploy the approved Quiet Margin candidate as the next product milestone. Preserve it as the current visual and interaction foundation, then reopen implementation around full Desktop parity.

The business model and onboarding strategy will be supplied in a separate founder voice note and should not be inferred beyond what is already recorded.
