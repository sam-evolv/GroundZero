# Personal agent interface, live work and time-given-back founder brief

## Founder direction

Sam will design the next interface himself. The product should begin from a familiar, exceptionally high-quality conversation rather than invent a new mental model for ordinary users.

The interface should feel easier and more useful than Telegram for agent work while preserving the conversational familiarity that makes Telegram effective. It should match or exceed ChatGPT's ease for chat and eventually its voice quality.

## Core interaction

One continuous conversation is the product's anchor. It must not expose Doing, Done, You, automations, skills, agents, Kanban, portals or capability catalogues as primary navigation.

On desktop, a contextual working surface may open beside the conversation when the assistant is browsing, comparing, creating or operating something visual. A person asking for DoneDeal car research should be able to watch the relevant work unfold without reading internal logs. The panel should close or recede when no longer useful.

On mobile, live work should open as a dedicated sheet or full-screen detail from the conversation rather than compressing chat into an unusable split view.

## Progress contract

Progress is a quiet trust layer, not the centrepiece and not simulated reasoning.

Project authoritative runtime events into short ordinary-language milestones such as:

- Looking through the listings
- Comparing the strongest options
- Checking the important details
- Preparing the result
- I need your approval before I do this
- Ready

Do not expose model, provider, agent, skill, tool, portal, Kanban, runtime or orchestration terminology. When work is divided internally, explain responsibility in human terms only if it helps: “I’m checking prices and ownership history at the same time.”

Show elapsed time while genuine work is active. Do not show chain-of-thought, fabricated narration or activity unrelated to the user's outcome.

## Time Given Back

Time returned is both a product value signal and a potential evidence-led marketing asset.

Per task, preserve:

- agent elapsed time;
- user active time spent clarifying, approving or correcting;
- a benchmark range for ordinary human active work;
- benchmark provenance and confidence;
- whether the task finished, partially finished or failed;
- any material human intervention.

Calculate conservative estimated time returned from a versioned methodology. Never treat elapsed runtime as equivalent to human labour, claim fake precision or include failed work as saved time. Present estimates as ranges until repeated observed task data supports tighter values.

Aggregate marketing claims should be derived only from completed, eligible tasks and retain an auditable evidence trail. Prefer “members have received an estimated 1,200 to 1,500 hours back” over an unsupported exact counter.

## Personal context and memory

Personal context is a long-term retention advantage, but it should feel like a useful relationship rather than a database.

The user should be able to inspect what is known, why it is known, what changed, confidence and recency, then correct or forget it. A growing relationship graph can be a compelling visual explanation of continuity, but users must not be asked to maintain nodes, edges, folders, tags or markdown.

Treat the visual graph as progressive disclosure or a memorable profile moment, not permanent primary navigation.

## Voice

Voice is first-class and should share one identity, conversation, memory, approvals and task state with text. It is not a separate assistant.

Hermes already provides transcription, text-to-speech and streaming-TTS infrastructure, but premium realtime conversation requires an instrumented WebRTC voice path with interruption, endpointing, Bluetooth and playback-truth testing. ChatGPT consumer subscription voice is not a commercial application integration path.

The founder alpha should compare a managed realtime speech path and a modular Hermes-controlled path on a real iPhone. The selection gate is measured end-to-first-audible-word latency, interruption quality, transcript accuracy, naturalness and long-session stability, not a studio voice demo.

## Naming

IrelandGPT remains a working repository and deployment name only. The final brand should scale beyond Ireland and should not depend on generic AI, agent, intelligence, assistant or operating-system terminology.

The naming target is short, pronounceable in Irish, British and American English, emotionally ownable, easy to hear once and spell, and capable of becoming natural speech if the product earns that behaviour. Verbability is a result of adoption, not something a name can guarantee.

No name is selected until trademark, company, domain, app-store and social checks are completed.

## Design sequence

1. Design the mobile conversation at 390px.
2. Design its desktop adaptation.
3. Add the contextual live-work panel on desktop and its mobile sheet equivalent.
4. Design real progress, elapsed time, approval, completion and failure states.
5. Design voice entry and active voice mode.
6. Design memory/profile as progressive disclosure.
7. Validate usability before expanding settings or secondary surfaces.

## Success tests

- Easier for Sam to use for real agent work than Telegram.
- No ordinary user must understand agent infrastructure vocabulary.
- One request can become visible, trustworthy work and a finished outcome without leaving the conversation.
- Live work helps comprehension rather than becoming spectacle.
- Time-saved claims are conservative, explainable and auditable.
- Voice feels natural under interruption and real-device conditions.
- Personal context improves results without becoming creepy or burdensome.
