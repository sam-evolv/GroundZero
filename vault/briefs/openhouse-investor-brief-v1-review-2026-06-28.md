# OpenHouse Investor Brief 1 Review

Reviewed 2026-06-28 from the PDF exported as `OpenHouse — Investor Brief 1.pdf`.

## Verdict

This version is meaningfully better than the previous version. It is more coherent, more premium, more investor-shaped, and the research recommendations are clearly reflected: one idea per slide, cleaner visual system, stronger category shift, more explicit developer wedge, Money / Comfort / Risk language, business model, Ireland-to-UK expansion, and appendix separation.

However, it is not finished. The biggest problems are:

1. The everyday property assistant is still underweighted.
2. Image upload and issue diagnosis are missing or not visible enough.
3. The construction-stage source-of-truth wedge is implied but should be more explicit.
4. The business model uses `$99` instead of `€99` and lacks the homeowner subscription pricing ladder.
5. Data ownership is present as a small trust guardrail, but deserves its own main-deck slide.
6. Agentic optimisation is mentioned but lacks a clear advisory → assisted → agentic roadmap.
7. The deck export includes visible browser URL/date/page footers and a likely OpalHouse/OpenHouse naming inconsistency, which must be fixed before sending.
8. The main deck is still likely 19 slides before appendix, rather than the target 12-15.

## Must-fix before sending

### 1. Remove export/browser clutter

The PDF visibly includes date, URL, page numbers, and browser-like side text around slides. This makes the deck look unfinished and exported from a preview page. Remove before sending to investors.

### 2. Fix brand naming

Some visible edge/footer text appears to say `OpalHouse` while the company is OpenHouse. Verify and fix everywhere. This is a trust-killer if sent externally.

### 3. Fix currency

Change `$99 per home` to `€99 per home`.

### 4. Add property assistant slide

There is still no strong day-one property assistant slide. Add one main-deck slide or modify Slide 9.

### 5. Add image upload / issue diagnosis

This should be visible in the product narrative, not only implied. Add phone mockup showing photo upload and routing.

### 6. Add proper data ownership slide

Current trust guardrail is too small. Include a full slide:
- homeowner controls personal and energy data
- developer supplies build/spec/warranty data
- OpenHouse owns software, structured model, diagnostics and anonymised aggregate intelligence
- developers receive portfolio insight, not household surveillance

### 7. Add agentic roadmap

Current deck mentions agentic roadmap but does not explain the trust ladder. Add or include:
- Advisory intelligence
- Assisted control
- Agentic optimisation
- consent, rules and override

### 8. Tighten to 15 main slides

Current main deck appears to run to around 19 slides before appendix. Aim for 15. Move data moat or expansion detail to appendix if needed, but do not cut product assistant, pricing, data ownership, or ask.

## Final judgement

This is substantially better. It now feels like a real investor deck rather than a strategy dump. The visual language is premium and the narrative spine is much clearer.

But it still slightly over-indexes on energy intelligence and under-indexes on the mundane property assistant that makes OpenHouse useful from day one. The current version shows the strategic expansion better than the adoption layer.

The next improvement should not be another full rewrite. It should be a surgical pass focused on:
- day-one property assistant
- image issue intake
- construction-stage wedge
- data ownership
- pricing correction
- export polish
- main-deck compression
